###################################################################################################
#  PROJECT PHASES
###################################################################################################

### PHASE 1: BPU LOGIC BRING-UP ###

This phase consists of bringing up the core Baseband processing unit (BPU). The STM32 firmware,
FPGA architecture, and communication interfaces are developed and verified. Simulated sample
streams are used in place of RF hardware.

Phase 1 exit requirements:
 - Boot both STM32 cores reliably
 - Configure and communicate with the FPGA
 - Send spoofed sample blocks from MCU to FPGA
 - Timestamp or schedule those sample blocks against FPGA ToD
 - Generate simulated 1PPS event
 - Emit deterministic digital sample stream at scheduled time
 - Verify resulting buses and timing

Phase 1 BOM:
 - STM32 development board (STM32H745I-DISCO)
 - FPGA development board (LFE5UM5G-85F-EVN)

Phase 1 bench equipment:
 - Bench PSU
 - Logic Analyzer


### PHASE 2: BASEBAND DSP INFRASTRUCTURE ###

This phase dwevelops the reusable DSP architecture that will become the foundation for every
supported radio mode. No RF hardware is required -- all signal sources remain simulated.

Phase 2 exit requirements:
 - Streaming DSP pipeline implemented
 - Implement FPGA FIFOs and DMA interfaces
 - implement NCO and digital mixers
 - Implement CIC filters
 - Implement FIR filter framework
 - Implement FFT engine
 - Verify DSP chain using simulated I/Q
 - Meet FPGA timing closure

Phase 2 BOM:
 - No additional requirements vs. phase 1.

Phase 2 bench equipment:
 - No additional requiirements vs. phase 1.


### PHASE 3: SYSTEM TIMING AND SCHEDULING ###

This phase develops deterministic timing architecture used throughout the radio. The FPGA becomes
responsible for aligning system time and frequency with GNSS input, and the MCU becomes able to
schedule future events against precise UTC ToD tracked by the FPGA.

Phase 3 exit requirements:
 - FPGA ToD counter synchronized to GNSS
 - Precisely scheduled future TX events
 - Timestamp API available
 - Characterize scheduling latency and jitter

Phase 3 BOM:
 - GNSS receiver development board

Phase 3 bench equipment:
 - Oscilloscope


### PHASE 4: RF MODULE BRINGUP ###

This phase introduces real RF hardware. The RF module is connected to the BPU, allowing live signal
reception and controlled trasmission.

Phase 4 exit requirements:
 - Establish communications with RF module
 - Receive live I/Q samples
 - Generate transmit sample stream
 - Verify ADC/DAC interfaces
 - Verify LO tuning
 - Perform receive calibration
 - Perform transmit calibration
 - Produce stable CW carrier

Phase 4 BOM:
 - RF hardware (TBD)
 - ADC/DAC hardware (TBD)
 - Power amplifier (TBD)

Phase 4 bench requirements:
 - RF spectrum analyzer
 - RF signal generator


### PHASE 5: FIRST DIGITAL MODE OPERATION ###

This phase finally brings up a full digital mode using the development hardware. FT8 as a complex
mode is used to demonstrate the capabilities of the hardware. This phase of operation requries an
initial bringup on user controls, but not yet formal consolidation of the user control module.

Phase 5 exit requirements:
 - Decode live FT8 transmissions
 - Display waterfall
 - Generate FT8 transmit waveform
 - Schedule transmissions correctly
 - Complete successful FT8 QSO
 - Demonstrate stable transmit/receive switching
 - Demonstrate user interaction through physical controls

Phase 5 BOM:
 - User controls

Phase 5 bench equipment:
 - Dummy load
 - RF watt meter


### PHASE 6: GENERAL-PURPOSE SDR ###

This phase expands the prototype into a flexible SDR platform suitable for experimentation and
future protocol development.

Phase 6 exit requirements:
 - Implement AGC
 - Implement configurable receive filters
 - Implement CAT interface
 - Implement logging
 - Implement SDcard recording
 - Implement configuration profiles
 - Support updates and external interfaces

Phase 6 BOM:
 - Production user control module prototype
 - SD storage

Phase 6 bench equipment:
 - No additional requirements vs phase 5


### PHASE 7: MULTI-MODE OPERATION ###

This phase fully generalizes the architecture so that new digital modes can be added with minimal
changes to the underlying infrastructure.

Phase 7 exit requirements:
 - Implement APRS
 - Implement WSPR
 - Implement generic framework for additional modes
 - Support runtime mode switching
 - Demonstrate modular waveform architecture
 - Document waveform API

Phase 7 BOM:
 - No additional requirements over phase 6

Phase 7 bench equipment:
 - No additional requirements over phase 6


### PHASE 8: CUSTOM HARDWARE & MOBILE OPERATION ###

This phase transitions from development boards on the bench to custom DigiR hardware. With the
architecture proven on the bench, custom hardware is built and manufactured enabling mobile ops.

Phase 8 exit requirements:
 - Custom BPU PCB
 - Custom RF module PCB
 - Custom power supply module PCB
 - Custom user control module PCB
 - Production enclosure
 - Final connectors and harnesses
 - mobile operation

Phase 8 BOM:
 - Production hardware (all 4 populated PCBs)
 - Production enclosure

Phase 8 bench equipment:
 - Soldering station
 - Hot air rework station
